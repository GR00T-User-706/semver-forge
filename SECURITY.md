# Security Policy

## Supported versions

Security fixes are provided for the latest supported release unless the project documents a different support policy.

## Reporting a vulnerability

Do not report exploitable vulnerabilities in public issues.

Use GitHub's private vulnerability reporting feature when enabled. Otherwise contact maintainers privately through the security contact configured in repository settings.

Replace this paragraph with a monitored security contact before making the repository public:
- Security contact: CONTACT_EMAIL

Include a clear description and impact, affected versions/configurations, reproduction steps or proof of concept, and known mitigations.

Do not include real user data, credentials, or unrelated personal information.

## Response

Maintainers will acknowledge reports as soon as practical, investigate validity and impact, coordinate remediation, and communicate disclosure timing with the reporter.

Please allow a reasonable period for remediation before public disclosure. Do not access, modify, or exfiltrate data beyond what is necessary to demonstrate the issue.
